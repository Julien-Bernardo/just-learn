**What's going wrong**

1. **`second` starts as `nums[0]`.** It's only updated when a new largest is found. So a value that falls *between* `second` and `largest` (like `4` in `[5, 1, 4]`) is never recorded. `second` stays at `5`.
2. **Duplicates of the largest aren't handled.** In `[5, 5, 3]`, `second` begins as `5`, and `3` is never considered, so you return `5`. The task wants the second largest *distinct* value, so `5` can't be the answer.
3. **Short or all-equal lists aren't handled.** `[7]` has no second distinct value, so you need to return `None`, but `second` was initialized to `nums[0]`.

**Fixed version**

```python
def second_largest(nums):
    largest = None
    second = None
    for n in nums:
        if largest is None or n > largest:
            second = largest      # old largest becomes second
            largest = n
        elif n != largest and (second is None or n > second):
            second = n            # n is between second and largest
    return second
```

**How it works**
- `None` means "not found yet", so `[7]` and `[]` return `None`.
- If `n` is a new maximum, the old maximum becomes `second`.
- Otherwise, if `n` is different from `largest` (this skips duplicates) and bigger than the current `second`, it becomes the new `second`.

**Quick trace on `[5, 5, 3]`**
- `n=5`: largest=5, second=None
- `n=5`: not > largest, and equals largest, so skipped
- `n=3`: 3 != 5 and second is None, so second=3
- returns `3`

**Alternative (shorter)**
```python
def second_largest(nums):
    s = sorted(set(nums))
    return s[-2] if len(s) >= 2 else None
```
This removes duplicates with `set`, sorts, and takes the second from the end. It's less efficient on huge lists, but fine for most assignments.
