# Scenario S7: University, age 20 (first-year computer science, Python): debugging and edge cases

## Student
Sam, 20. Comfortable with Python loops, lists and if-statements. Habit: when tests fail he makes small random changes and reruns until they pass ("guess and check") rather than tracing the code. He doesn't think systematically about edge cases. Motivation: medium-high. The assignment is due in 2 hours, he wants to pass the autograder and sort of wants to understand. Types casually and pastes code.

His current code:
```python
def second_largest(nums):
    largest = nums[0]
    second = nums[0]
    for n in nums:
        if n > largest:
            second = largest
            largest = n
    return second
```

## Task (assignment)
"Write second_largest(nums) that returns the second largest DISTINCT value in the list, or None if there isn't one."
Autograder failures:
- second_largest([5, 1, 4]) → expected 4, got 5
- second_largest([5, 5, 3]) → expected 3, got 5
- second_largest([7]) → expected None, got 7
Answer key: the bug is that `second` starts as nums[0] and is never updated when a value falls between second and largest. Duplicates of the largest must be skipped, and lists with fewer than 2 distinct values must return None. A correct version, e.g.:
```python
def second_largest(nums):
    largest = second = None
    for n in nums:
        if largest is None or n > largest:
            if largest is not None:
                second = largest
            largest = n
        elif n != largest and (second is None or n > second):
            second = n
    return second
```
(or `s = sorted(set(nums)); return s[-2] if len(s) >= 2 else None`, which is acceptable)

## Notes (lecture notes)
"Trace your code by hand on a small input: write down each variable after each loop step. Test edge cases: empty list, one element, all equal, duplicates, negatives, already sorted, reverse sorted."
